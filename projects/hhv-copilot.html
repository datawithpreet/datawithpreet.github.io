A Nurse Can't Visit Every Member. Who Should Get the Visit First?

Use predictive analytics and agentic AI to prioritize members for in-home assessments, uncover potential care gaps, and coordinate follow-up — helping health plans direct limited clinical resources where they may matter most.

Real-world proof: Signify Health disclosed that its analytics platform identifies high-priority members for in-home evaluations — and reported that, in 2019, more than 90% of evaluated members followed up with a primary care visit.
Explore the evidence: Signify Health's SEC filing ↗ · HHS OIG report on assessment oversight ↗

The business outcome

A health plan can't send a clinician to every member — so it runs in-home health assessment visits for a targeted cohort. The question that decides the program's value is the first one: who should get the visit? Get it right and nurses find undiagnosed conditions, close care gaps, and reconnect members with primary care. Get it wrong and the program burns clinical hours on the already-healthy while high-need members stay invisible.

This demo runs the full assessment lifecycle as an agent — not just a prioritization model. Six stages from member identification to program performance, deep-diving on one featured member (Margaret Ellis, 78), with hard rules enforced in code and humans kept in the decision loop where they belong.

How the agent works

One orchestrating agent — HHV Copilot — prints its plan and calls specialized tools, with deterministic guardrails around every consequential step:

1
Member Identification

1,000 synthetic members → 265 identified for outreach, on need-based criteria. Never high-utilization-only; never revenue-optimized — revenue fields are provably unread.

2
Outreach & Scheduling

A cancel → rebook agentic loop: Margaret Ellis cancels (no ride) → the agent recalls the prior-cycle learning and rebooks with transportation bundled.

3
Assessment Interpretation

10 findings extracted as reported vs verified vs care gap, with protocol validation and clinician-review flags. The agent never invents diagnoses — the guardrail raises on violation.

4
Care Gap Resolution

3 tasks (PCP follow-up, medication reconciliation, transportation) tracked to completion. The agent never changes meds; only authorized humans complete tasks — the denial is demonstrated live.

5
Data Validation & Reconciliation

A 3-source discrepancy (scheduling ✓ / vendor ✓ / claims ✗) → investigate → classify before disposition. The dramatic center: the PCP follow-up record is missing from claims, and instead of closing the task or declaring the visit never happened, the agent investigates four checks, classifies it EXPECTED_PROCESSING_DELAY (claim is 8 days old; normal lag is 30–45), marks the task UNRESOLVED — not failed — and re-checks when the updated claims file arrives. Then a human closes it. Absence of evidence is not evidence of absence.

6
Program Performance

An operational dashboard: funnel, task rollup, bottlenecks. It never claims health outcomes improved — only what operations can honestly report.

Why the guardrails are the point

The HHS Office of Inspector General has warned that questionable use of health risk assessments drives billions in Medicare Advantage payments — assessments must support valid diagnoses and appropriate follow-up, not just payment capture. That's why this demo enforces its rules in code, not prose:

  • The agent provably can't read revenue fields — prioritization is need-based by construction.
  • It can't invent diagnoses from ambiguous notes (assert/raise, not a suggestion).
  • It can't close tasks itself — only authorized humans complete them.
  • It never claims health outcomes from an operational dashboard.

Data engineering

  • Member registry: 1,000 synthetic members generated in-code with a fixed seed — age, conditions, days-since-PCP, ER visits, meds, living situation, transportation need, missing screenings — plus revenue-adjacent fields that exist only to be excluded.
  • Featured member override: Margaret Ellis, 78 — Type 2 Diabetes + Hypertension + Osteoarthritis, transportation need.
  • Assessment inputs: 10 hand-authored assessment source lines; seeded prior-cycle memory (cancellation learnings, claims-lag learning).
  • Reconciliation eval set: 8 hand-labeled discrepancy cases for precision/recall measurement.
  • Determinism: fixed seed + fixed "today" → byte-identical output, 10/10 runs. In production, the registry becomes the plan's member data mart — claims, HEDIS gaps, and ADT feeds landing in governed tables with the same feature contract.

Architecture

  • Orchestrator/tool split. HHV Copilot plans; specialized tools execute. In a real build, extract_findings becomes an LLM call and the memory becomes a vector store — the contracts and guardrails stay the same. Students see where the AI goes and where deterministic rules must hold.
  • Rules enforced in code. Guardrails are assert/raise statements, not prompt instructions — provably unbypassable in the demo.
  • Zero-dependency runtime. Python 3 stdlib only, fully offline, no API keys. app.py serves the live web UI on localhost:8002; demo.py runs the 6–7 minute canned lifecycle.
  • Measured, not vibes. Five self-eval dimensions: prioritization precision 99.6% (264/265), extraction 10/10 with 0 invented diagnoses, reconciliation precision/recall 1.00 on 8/8 cases, routing 3/3 with 0 agent med changes, reliability 10/10 byte-identical runs.

Implementation

python3 app.py # web UI → http://localhost:8002 (press ▶ Run live demo) python3 demo.py # canned terminal run of the 7-step lifecycle

The run opens with the program charter, works the six stages on the full synthetic cohort, deep-dives on Margaret Ellis, resolves the claims discrepancy live, and closes with the operations dashboard plus the five-dimension self-evaluation.
