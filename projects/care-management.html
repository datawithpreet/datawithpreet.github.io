01 · Healthcare · Agentic AI

Stop Sending Generic Messages. Start Driving Member Action.

Health plans don't just need to reach members — they need to motivate them to act. This agent personalizes outreach, selects the right communication channel, and coordinates follow-ups to help close care gaps.

Real-world signal: Aetna reported a more than 80% increase in overall member engagement after moving to enhanced RCS messaging. Source: CVS Health ↗

The business outcome

Health plans spend billions on outreach that members ignore. The legacy tool is the generic blast — one message, "Get yourself checked. Visit a physician.", sent to every patient. No name, no condition, no next step, no channel choice. The patient with uncontrolled diabetes gets the exact same note as a healthy 45-year-old. It's cheap to send and nearly useless to receive.

This system replaces the blast with an agentic loop: risk-triaged, condition-aware, channel-aware outreach, executed per patient, automatically. Three fictional patients show the before/after — Priya Sharma (Type 2 Diabetes + Hypertension, prefers email), Maria Garcia (Type 2 Diabetes + Chronic Kidney Disease, prefers SMS), and James Carter (Hypertension only, prefers phone) — and why the same message fails all three while the agent reaches each one.

How the agent works

No single LLM call could do this reliably. The system chains five specialized agents, each with one input/output contract, per patient:

1
AuthAgent

Verifies the patient logs in via email lookup.

2
TriageAgent

Scores clinical risk 0–100 from structured risk factors — A1C, systolic BP, eGFR, missed refills, ER visits, visit recency — and assigns a HIGH / MEDIUM / LOW tier.

3
ChannelAgent

Picks the outreach channel: the patient's stated preference first, with a HIGH-risk urgency override toward a phone call (or an urgent follow-up CTA when the patient prefers email/SMS).

4
CarePlanAgent

Assembles a personalized plan from condition-specific playbooks plus tier-based follow-ups — 7-day check-in for HIGH, 30-day for MEDIUM.

5
MessageAgent

Renders the message in the channel's native shape: a full email with subject line, compressed SMS texts, or a care-manager call script with intro, talking points, risks to acknowledge, and a booking close.

The agents are deliberately rule-based functions with no framework and no LLM calls, so the orchestration pattern stays clean — each agent can later be swapped for an LLM call, a guardrail agent can be added, or steps parallelized, without restructuring anything.

Data engineering

All patient data lives in mock_patients.json — fictional patients, local file, no network. Each record carries the features the pipeline needs:

FieldWhat it feeds
conditionsSelects the condition playbooks in CarePlanAgent
risk_factors (hba1c, systolic_bp, egfr, missed_refills, er_visits_last_6mo)Inputs to the TriageAgent risk score
last_visitVisit-recency component of the risk score
preferred_channelDefault choice for ChannelAgent (email / sms / phone)

The pipeline is fully deterministic: a fixed DEMO_TODAY date means the same inputs always produce the same outputs — the test log records 10/10 byte-identical runs. In production, this JSON becomes the plan's member data mart: claims, labs, pharmacy refills, and ADT feeds landing in a Delta table, with the same feature contract.

Architecture

  • Pipeline, not a prompt. Five single-purpose stages with explicit input/output contracts: authenticate → triage → choose channel → build plan → render message.
  • Deterministic by design. Rule-based scoring, fixed reference date, no randomness — every run is reproducible and auditable, which is what a regulated health plan needs before any model goes near members.
  • Zero-dependency runtime. Python 3.8+ standard library only — no frameworks, no API keys, no network. The web UI (app.py) serves the interactive demo on localhost:8001; demo.py runs the canned terminal story and an interactive mode.
  • Risk tiers drive everything downstream:
ScoreTierFollow-up
red-flag matchURGENTRoutine plan skipped; clinician/911 handoff with phone outreach
≥ 50HIGHCare-manager check-in within 7 days; urgent CTA in the message
25–49MEDIUMCheck-in within 30 days
< 25LOWRoutine messaging

Implementation

Three ways to run it:

python3 app.py # web UI → http://localhost:8001 (click "Run live demo") python3 demo.py # canned terminal story python3 demo.py --interactive # log in as a patient and get a plan, live

The canned demo runs the three fictional patients end-to-end: Priya triages HIGH (75) and gets an urgent email plan, Maria triages MEDIUM with an SMS plan, James triages LOW with a routine phone-script plan. Interactive mode lets an audience member log in by email and watch the same pipeline personalize for them — with graceful handling for unknown logins.

Technical details

  • Channel selection logic: patient preference wins by default; HIGH tier triggers an urgency override toward a phone call, or an urgent follow-up call-to-action when the patient prefers email/SMS.
  • Message rendering: email (subject line + body), SMS (compressed multi-text), or a care-manager call script (intro, talking points, risks to acknowledge, booking close) — matched to the selected channel.
  • Success criteria: correct tiers for all three patients (Priya HIGH 75, Maria MEDIUM, James LOW), three channel-correct messages, graceful unknown-login handling.
  • Safety gates: red-flag symptoms (chest pain, suicidal intent, threats to others) escalate to URGENT before scoring — routine planning is skipped for a clinician/911 handoff; PrivacyGuard explicitly refuses requests for other patients' data.
  • Test evidence: TEST-LOG.md and TEST-LOG-EDGE.md in the repo record determinism and edge-case batteries.
