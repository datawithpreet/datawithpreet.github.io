Your Resume Gets 7 Seconds. Make Every One Count.

Job seekers send resumes into a black box and never learn why they hear nothing back. Resume Reviewer AI is an agentic system that scores your resume against 33 explicit hiring-manager rules plus the actual job description — with evidence for every failure and a concrete fix — instantly, and privately in your browser.

Real-world signal: Ladders’ 2018 eye-tracking study found recruiters spend an average of just 7.4 seconds on the initial resume screen — scanning for name, titles, dates, and education, not reading.
HR Dive: Eye-tracking study shows recruiters look at resumes for 7 seconds ↗

The business outcome

I get asked constantly: “Can you review my resume?” One-by-one reviews don’t scale, and generic online checkers give vague advice (“add more action verbs!”) without checking the things hiring managers actually reject resumes for — a missing LinkedIn, two email addresses, a scanned PDF no ATS can read, or zero overlap with the job description’s skills.

The outcome this project delivers: a checklist with teeth. Upload your resume (PDF or Word), paste the job description you’re targeting, and the agent runs 33 hiring-manager rules — 15 for the header (contact block, LinkedIn, location) and 18 for the body and formatting (action verbs, quantified bullets, tense consistency, buzzwords, ATS-friendly layout) — plus two conditional integrity checks (keyword-stuffing evidence, garbled-text detection) and a job-description skill match that names exactly which required skills are missing. Every failed rule comes with evidence from your resume and a concrete fix. And it’s private by design: everything runs in your browser — the resume never leaves your tab.

How the agent works

One orchestrator, five capability groups — deliberately not five separate agents. One decision-maker, one audit trail, one score. The full loop:

1
Ingest & validate

Name present, LinkedIn URL matches linkedin.com/in/..., job description non-trivial, file is PDF or DOCX. Files over 5MB warn but proceed; scanned/image PDFs are rejected with a clear message instead of scoring garbage.

2
Extract

PDF.js yields text plus line layout, font sizes, and embedded-image count; mammoth extracts DOCX text. Layout-aware rules (name prominence, photo detection, font size) gracefully degrade to “manual check” when the source can’t provide the signal — the agent says what it couldn’t verify instead of guessing.

3
Verify

All 33 rules run (plus the two conditional integrity checks when triggered), then the JD skill-match: a ~90-term skill lexicon (data-engineering heavy) is matched against the job description, and each JD skill is checked against the resume.

4
Score & explain

Score = 70% rules + 30% JD skill coverage, 0–100, graded Excellent / Strong / Fair / Needs work. Every failure prints what was seen (“Found 2 emails: …”) and the fix (“Keep one email…”). Missing JD skills are listed with an honesty rule: add the ones you truly have — never invent skills.

5
Notify

Fire-and-forget POST of metadata only (name, LinkedIn, timestamp, score, JD title) to my inbox. Best-effort by design: a notification failure never blocks the user’s report — and the resume itself is never sent.

Data engineering

The interesting data problem here isn’t scale — it’s determinism across two runtimes. The same rule engine exists twice: Python (rules_engine.py) for the CLI and JavaScript (resume-reviewer.js) for the browser. Both share identical rule semantics (Python is the reference implementation; the browser engine mirrors it — see README’s sync checklist): fixed CURRENT_YEAR (2026), sorted iteration everywhere, no randomness, no timestamps in scoring. A 47-assertion test suite (test_rules.py) gates every change — strong fixtures must score ≥ 85, weak fixtures ≤ 55 with ≥ 12 rules failing, edge fixtures (no contact info, scanned PDFs) must never crash, and TEST-LOG.md records the JS↔Python byte-identical check.

Implementation

Run it locally in about a minute:

  • python3 app.py, then open http://localhost:8009/resume-reviewer.html in Chrome
  • Paste a job description, upload any PDF resume, click Review my resume
  • Terminal fallback: python3 demo.py fixtures/strong.txt fixtures/sample-jd.txt

Key files in ynpreet/resume-reviewer-agent: web/resume-reviewer.html (form + results UI), web/assets/js/resume-reviewer.js (JS rule engine + PDF/DOCX extraction), rules_engine.py (shared Python engine), demo.py (stdlib CLI), test_rules.py (38 assertions), fixtures/ (strong, weak, edge cases).

Technical details

  • Scoring: 0–100 = 70% rule pass rate + 30% JD skill coverage; grades Excellent / Strong / Fair / Needs work.
  • Breakdown: Header x/15, Body & Formatting x/18, JD skill match % — per-section bars show exactly where points were lost.
  • Honesty rules: layout signals the parser can’t verify become “manual check” flags for human eyes; the JD panel tells users to add only skills they truly have.
  • Failure modes handled: scanned PDFs rejected with a clear message, DOCX without font data degrades gracefully, empty job descriptions blocked at ingest.
