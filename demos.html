From chatbots that answer to agents that do

For years, AI meant a chatbot: you ask a question, it gives you an answer. Useful — but the work still landed on your desk. That era is ending. The world is moving toward agentic AI: systems that don't just answer, they plan, use tools, make decisions, and ask for help when they're unsure.

Think about the tools you already trust. A travel assistant that doesn't just suggest flights but books them, rebooks when the flight is cancelled, and messages you the new plan. A health app that notices you missed a checkup, calls the clinic, and puts the appointment on your calendar. Customer support that doesn't hand you a help article — it looks up your order, finds the problem, and fixes it. A coding assistant that writes the code, runs the tests, and fixes the failures. Every one of these is an agent: a loop of observe, decide, act — with you able to step in at any point.

This matters now because the barrier has collapsed. You no longer need a research lab to build one: the demos below were built with plain Python, no paid APIs, no special hardware. If you understand a workflow — the steps, the tools, the judgment calls — you can turn it into an agent. That makes agentic AI the most practical AI skill to learn today: it applies to healthcare, finance, retail, gaming, and everywhere decisions get made.

Eight demos run on your own computer — each one a complete agentic system, not a slide deck. The ninth, Resume Reviewer AI, runs entirely in your browser.

How to run

No IT background needed — if you can open a web browser, you can run these. Each demo opens as a website on your own computer: you click through the story in Chrome, no coding required. Nothing is installed, no accounts, no API keys. The whole thing takes about 5 minutes the first time.

Two ways to run

Option A — Just one demo

Pick a demo below, run its three commands, and open the address in Chrome. Each demo's exact commands and port are listed in its block.

git clone https://github.com/ynpreet/<demo-repo>.git cd <demo-repo> && python3 app.py open http://localhost:<port> in Chrome

Option B — All nine at once

One command from the agentic-ai-demos repo clones anything you're missing and starts every demo on ports 8001–8009. Open any address — only the port number changes. Ctrl+C stops everything.

git clone https://github.com/ynpreet/agentic-ai-demos.git cd agentic-ai-demos && python3 run_all_demos.py open http://localhost:8001 … http://localhost:8009 in Chrome

Ports — 8001 Care · 8002 HHV · 8003 Restaurant · 8004 AeroYield · 8005 Music · 8006 FixMate · 8007 GameGuard · 8008 GuestFirst · 8009 Resume Reviewer

No git? Open any demo's GitHub page below, click the green <> Code button → Download ZIP, unzip it, open a terminal in that folder, and run python3 app.py (keep the terminal open). Then open its http://localhost:<port> address in Chrome. Prefer the classic terminal version? Run python3 demo.py instead of app.py — same story, text only.

Building your own agent? Start here.

These are the do's and don'ts distilled from teams shipping agents in production — the practices that separate demos that impress from systems that survive real users. General builder guidance, not a rulebook: use it as a pre-flight check before you build, and again before you ship. The full version covers problem definition, agent design, safety, testing, and operations.

The Agentic AI Builder's Checklist

5 sections, 44 one-line rules: before you build, designing the agent, safety & trust, testing & evaluation, shipping & operating. Keep it next to your keyboard.

Download the full checklist (PDF)

✓ Do

  • Write down the exact task the agent performs, in one sentence, before touching any code.
  • Start with the simplest thing that could work: one model call, one tool, a fixed sequence of steps.
  • Design a few clear, well-named tools instead of dozens of vague ones.
  • Decide up front which decisions the agent may make alone and which need a human's approval.
  • Put a human checkpoint before any irreversible action: sending, paying, deleting, publishing.
  • Treat user-provided content as untrusted data — never let it become instructions the agent follows blindly.
  • Build 10–15 realistic test scenarios (including failure cases) and run them after every change.
  • Track cost and latency per task from day one — agentic loops multiply both.

✗ Don't

  • Don't build an agent for a task you can't describe in plain words.
  • Don't hand the agent full autonomy on day one — earn it with evidence.
  • Don't let the agent act on text it read from the open web as if it were your instruction.
  • Don't grant the agent broader permissions than the task needs.
  • Don't ship without a way to turn the agent off quickly.
  • Don't evaluate on two perfect demo inputs and call it tested.
  • Don't launch to all users with the same settings you used in testing.
  • Don't ignore cost until the invoice arrives — set budgets and alerts.
